# 請進 快剪｜線上看號

客人掃 QR Code 就能即時看到「目前叫到幾號」、還有幾人在等、預估要等多久、
每位設計師的狀態和休假，也能輸入自己的號碼查「前面還有幾位」。

店內：客人在抽號機投幣後，按一下底部的「不指定」（要指定設計師就按「指定」再選人）；
設計師剪完，按一下**自己名字的按鈕**就是叫下一號，系統會**先叫指定他的客人，沒有的話再叫不指定的**。


| 頁面 | 網址 | 誰用 |
|---|---|---|
| 客人頁 | `https://你的網址/` | 客人掃 QR Code |
| 操作頁 | `https://你的網址/staff.html` | 設計師（店內密碼）、店長（店長密碼） |

> 這套系統**不取代**店裡的抽號機：客人照樣在機器投幣、拿號碼牌，
> 系統的號碼跟著機器走（每按一次「加號」就 +1），漏按時可以用「補號」對齊機器。

## 先試玩（不用任何設定）

`config.js` 的 `supabaseUrl` 留空時是**示範模式**，資料只存在這台電腦的瀏覽器。

- **最快**：打開 `preview.html`，客人頁和操作頁兩個畫面並排，而且是連動的
- 或分開開：`index.html`（客人頁）＋ 同一個瀏覽器另一個分頁 `staff.html`（操作頁）
- 店內密碼 `111111`、店長密碼 `999999`

> 有些瀏覽器直接雙擊檔案打開會擋掉分頁同步，可以在資料夾裡執行 `npx serve .`，再用 `http://localhost:3000` 開。

## 正式上線（約 20 分鐘）

### 第 1 步：申請 Supabase（存號碼的雲端資料庫，免費）

1. 到 <https://supabase.com> 用**你自己的 Email** 註冊，按 **New project**
   - Name：`qingjin`
   - Region：選 **Northeast Asia (Tokyo)** 或 **Southeast Asia (Singapore)**，離台灣近比較快
   - 資料庫密碼自己設一組，記起來
2. 建好後，左邊選單 **SQL Editor** → **New query**
3. 打開本資料夾的 `supabase/setup.sql`，**先改最上面的兩組密碼**（至少 6 位數字）：
   ```sql
   '111111'::text  as staff_pin,   -- ★ 店內密碼（設計師共用）
   '999999'::text  as owner_pin;   -- ★ 店長密碼
   ```
4. 整份貼進 SQL Editor，按 **Run**，看到 `Success` 就完成了
5. 左邊選單 **Project Settings → API Keys**（或 **Data API**），複製兩個值：
   - **Project URL**：像 `https://abcdefgh.supabase.co`
   - **Publishable key**（或舊版的 **anon public** key）：這把是設計給網頁公開使用的，放進網頁沒關係
   - ⚠️ **不要**複製 `service_role` / `secret` 那一把

### 第 2 步：填入 config.js

```js
supabaseUrl: 'https://abcdefgh.supabase.co',
supabaseKey: '剛剛複製的 publishable / anon key',
```

### 第 3 步：放上 Netlify（免費網址）

**方法 A：拖拉上傳（最簡單）**
1. 到 <https://app.netlify.com> 註冊登入
2. **Add new site → Deploy manually**
3. 把整個 `quickcut` 資料夾拖進去
4. **Site configuration → Change site name** 改成 `qingjin`，網址就是 `https://qingjin.netlify.app`

**方法 B：連 GitHub（之後改程式會自動更新）**
1. **Add new site → Import an existing project** → 選這個 repo
2. **Base directory** 填 `quickcut`，**Publish directory** 填 `quickcut`（或留空），Build command 留空
3. 一樣把 site name 改成 `qingjin`

> 建議抽號系統用**獨立的 Netlify 帳號**，跟處方葉官網分開。免費額度用完時，整個帳號的網站都會被暫停，分開比較安全。

### 第 4 步：店內設定

1. 每位設計師用手機打開 `https://qingjin.netlify.app/staff.html`
   - 輸入店內密碼，之後打開就直接進入叫號畫面
   - iPhone：Safari 分享 →「加入主畫面」，就會像 App 一樣
2. 江江進「店長設定」：
   - **排休**：選設計師 → 點日期
   - **QR Code**：截圖或列印，貼在店門口、抽號機旁邊

## 日常使用

- **加號**：客人投幣拿到號碼牌，按操作頁底部的「不指定」；要指定設計師就按「指定」選人。連續有人投幣就連按，每一下都會算。
- **客人拿號後才說要指定**：在「等候名單」點那一號 → 選設計師。
- **漏按加號、跟機器對不上**：在等候名單下方輸入「機器發到幾號」→「補號」，中間漏掉的號碼會補成「不指定」。
- **按錯加號**：「取消最後加的一號」。
- **叫號**：操作頁上一位設計師一顆按鈕（名字＋服務中的號碼），**按一下就是叫下一號**。按錯就點提示訊息上的「退回」（5 秒內）。
- **長按名字按鈕**：過號、叫指定號碼、休息／回來、退回。
- **叫號規則**：按下去 → 先叫**指定這位設計師**、號碼最小的；沒有的話叫**不指定**、號碼最小的；都沒有就顯示「目前沒人等候」，這位設計師在客人頁會變成「空檔中」。
- **過號**：叫了客人沒出現，長按名字 →「過號」，會直接叫下一位。過號的號碼會用**橘色**列在等候名單下方。
- **過號的客人回來了（要再等 3 位）**：在等候名單點他的橘色號碼 →「客人回來了」，系統會把他排在**目前等候第 3 位的後面**（等候不到 3 位就排最後）。客人頁查號碼也會顯示「已過號，回來後要再等 3 位」。
  - 要改成等幾位：`config.js` 的 `skipRejoinAfter`，和 `supabase/setup.sql` 裡 `rejoin` 的 `offset 2`（＝第 3 位）要一起改
  - 急的時候也可以長按名字 →「叫指定號碼」直接叫他
- **按錯**：點提示上的「退回」，或長按名字 →「↶ 退回」。剛叫的那位回到等候名單，上一位回到「服務中」。
- **每天自動歸零**：每天第一次操作時，自動從 001 開始。不用手動歸零。
- **老闆休假**：其他設計師照常叫號。四位設計師的按鈕都在同一頁，任何一支登入的手機都能幫任何人按。
- **密碼打錯 10 次**：鎖 10 分鐘。

## 預估等候時間、「現在人少」與人潮圖

- **預估等候時間**：有在用「加號」時，系統會**自動估算**：等候人數 × 每位平均分鐘數 ÷ 在班的設計師人數（平均分鐘數在 `config.js` 的 `avgCutMinutes`，預設 12 分鐘）。
  - 客人輸入自己的號碼，也會看到「前面還有幾位、預估等多久」；指定設計師的客人只算指定同一位的
  - 不需要任何人手動輸入；準不準取決於每位客人都有按「不指定／指定」加號

- **現在人少**：客人頁頂端顯示「現在人少，到店幾乎不用等」。
  - 有在用「加號」時：沒有人在排隊、而且有設計師空檔，才顯示
  - 都沒有時，改看設計師：在班、沒休息、超過 20 分鐘沒叫號，就當作「空檔中」
  - 剛上班的 15 分鐘內不算，避免開門時門口有人在等卻顯示人少
  - 分鐘數可以在 `config.js` 的 `idleMinutes` 調整（快剪一位約 10～15 分鐘，所以預設 20）
  - **前提是大家每一位都有按叫號**，漏按的話會誤判成空檔
- **什麼時候來最不用等**：用過去 8 週的叫號紀錄，算出每個星期幾、每個小時平均剪幾位，並標出當天最不用等的兩小時。
  - 累積滿 **14 天**才會顯示，資料太少容易誤導客人
  - 示範模式顯示的是假資料（畫面上會標示「示範資料」）

## 更新程式後

`supabase/setup.sql` 有改動時，到 Supabase SQL Editor **整份再執行一次**即可升級，既有資料和密碼都不會被清掉。

## 改店家資料

全部在 `config.js`：營業時間、電話、地址、設計師班表。
**新增或刪除設計師**時，`config.js` 和 `supabase/setup.sql` 底部的設計師名單要**一起改**，再到 SQL Editor 執行一次 `setup.sql`（不會清掉既有資料）。

## 數據：會記錄什麼、怎麼看

### 會記錄什麼

| 資料表 | 內容 | 誰看得到 |
|---|---|---|
| `tickets` | 每張號碼牌的抽號（到店）時間、叫號時間、指定哪位、實際誰剪、有沒有過號 | 客人只看得到號碼和狀態（沒有個資）；完整資料只有後台 |
| `call_log` | 每一次加號、叫號、過號、過號回來的紀錄 | 只有後台 |
| `page_views` | 客人頁使用量：幾點有人打開、查號碼，是不是掃門口 QR Code 來的 | 只有後台 |

客人頁使用量**完全匿名**：每台手機每天產生一個隨機代號，只用來算「幾個人」，隔天就換。同一人 10 分鐘內重複打開只算一次。
店門口的 QR Code 會自動帶上 `?src=qr`，所以分得出「掃 QR Code」和「別人分享的連結」。

### 上線後怎麼看

1. 登入 <https://supabase.com> → 進入專案 → 左邊 **SQL Editor**
2. 打開本資料夾的 `supabase/reports.sql`，**複製其中一段**（每段開頭有 ①②③…）貼上 → **Run**
3. 下方就是結果表格；右上角可以 **下載 CSV**，用 Excel 或 Google 試算表打開
4. 常用的那幾段按 **Save** 存起來，之後點一下就能重跑

| 報表 | 看什麼 |
|---|---|
| ① 每日總覽 | 每天發號、平均／最長等候、過號率、客人頁使用人數、查號比例 |
| ② 每週趨勢 | **看改善最清楚的一張**：平均等候、過號率、離峰占比、查號比例，一週一列 |
| ③ 冷熱時段 | 每個星期幾 × 每小時，平均到店人數和等候時間 |
| ④ 設計師 | 每位服務人數、被指定人數、指定率 |
| ⑤ 客人頁使用時段 | 客人都在幾點打開、查號碼 |

- 「離峰」在 ② 裡定義為**平日 09–11 點、14–17 點**，可以直接改 SQL 裡那一行
- 建議每週看一次 ②，記下每一週的數字
- **準不準，取決於每位客人投幣後都有按「不指定／指定」**。每天打烊前，可以對一下抽號機的號碼，漏按的用「補號」補齊

### 案例對外公開時

建議用**百分比和變化量**（例如「過號率下降 40%」「離峰占比提高 8 個百分點」），不放絕對人數和營業額，並且先給老闆看過、同意後再公開。

## 用量與費用

一間店每天約 300 人的規模，Supabase 和 Netlify 的**免費方案都夠用**。

- Supabase 免費專案**閒置 7 天會暫停**（店家每天使用就不會觸發）。
- 正式營運建議升級 Supabase Pro（有每日備份）。
